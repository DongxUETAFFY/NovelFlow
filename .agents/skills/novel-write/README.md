# novel-write

`novel-write` 是 NovelFlow 的写作 Skill，用于章节续写、片段续写、批量写作、审查、checkpoint，以及断书续写到完结。

它读取 `novel-setup` 创建的 `novel/` 项目，并把长篇写作拆成三件事：

- 写正文。
- 审查硬错误和关键风险。
- 把章节变化整理成可持续使用的项目状态。

## 模式

| 触发 | 模式 | 行为 |
|------|------|------|
| `free draft`、`试写`、`不更新状态` | 自由草稿 | 只写草稿，不更新状态 |
| `续写这段`、`接着这段写` | 片段续写 | 以用户片段为局部锚点续写，不自动并入正文 |
| `continue`、`下一章`、`写第 N 章` | 标准写作 | 写一章，生成轻量 delta，更新必要状态 |
| `production lock`、`严格模式` | 生产锁定 | 完整 delta、审查、状态重建和硬性校验 |
| `batch 5`、`连续写 3 章` | 批量写作 | 默认生产锁定 |
| `write all`、`一口气写完` | 全自动 | 先提示质量风险，再按安全门推进 |
| `续写到完结`、`这本书断了` | 断书接诊 | 先输出诊断报告和续写路线图 |
| 路线图确认后 | 完结续写 | 固定生产锁定，逐章写到结尾 |
| `review` | 审查 | 审查已有章节并给出修复建议 |
| `checkpoint`、`十章检查` | Checkpoint | 全局一致性、节奏和伏笔健康检查 |

## 每章流程

```text
Step 0: 从 context-brief.md 恢复入口状态
Step 1: 按模式装配上下文
Step 2: 识别当前章节的里程碑和硬约束
Step 3: 静默生成场景蓝图
Step 4: 先写正文
Step 5: 审查硬错误；生产锁定时运行完整清单
Step 6: 创建 chapter delta 并验证
Step 7: 更新章节、摘要、动态状态、伏笔账本、进度和 context-brief
Step 8: 暂停，等待作者反馈
```

## 质量层级

| 层级 | 生效范围 |
|------|----------|
| P0/P1/P2 风险分类 | 标准写作和生产锁定 |
| 章节 delta 校验与提交 | 正式章节 |
| 生成态重建 | 正式章节 |
| 伏笔过期和状态漂移 audit | 长自动化、旧章改动、生产锁定 |
| 结构健康检查 | 生产锁定；标准写作只做软提示 |
| milestone 保护 | 生产锁定硬执行；标准写作软提示 |
| full-auto 安全门 | 全自动模式 |

## 片段续写

片段续写默认不是正式章节推进。它只续写用户给出的片段，并明确说明没有更新项目状态。

如果需要保存草稿，可使用：

```bash
python skills/novel-write/scripts/novelflow.py save-fragment-draft --novel-dir novel --text-file draft.md
```

只有作者明确要求“并入正文”或“保存到第 N 章”，才切换到标准写作流程。

## 断书续写

断书续写分两段：

1. **Finish Book Intake**
   输出诊断报告和路线图，不写正式章节，不更新状态。

2. **Finish Book Run**
   作者确认路线图后进入，固定生产锁定，逐章写作并提交完整 delta。

## 上下文压缩

写第 C 章时，默认上下文包括：

| 距离 | 压缩方式 | 用途 |
|------|----------|------|
| C-1 | 全文 | 文风和即时连续性 |
| C-2 到 C-3 | 完整摘要 | 近期剧情 |
| C-4 到 C-6 | 摘要前 100 字 | 关键事件 |
| C-7 到 C-10 | 摘要前 50 字 | 主要转折 |
| 更远章节 | 一句话摘要 | 长期记忆 |

## 依赖

至少需要：

```text
novel/context-brief.md
novel/outline.md
```

推荐完整项目由 `novel-setup` 创建。详细流程见 `SKILL.md` 和 `references/` 下的模式说明。
